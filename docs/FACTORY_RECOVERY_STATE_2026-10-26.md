# Factory: восстановление состояния из проверенного архива

Дата: 26.10.2026. Ветка: `feat/calculator-t02-charge-reconcile-20261022`. PR #75 остаётся черновиком. Main, Onay и Calculator не изменялись; merge и deployment не выполнялись.

## Результат

Добавлен `restoreCalculatorRecoveryState`: восстановление сохранённого плана, planning receipt и всех указанных квитанций до текущей задачи из подлинной capability проверенного GitHub artifact. Сверяются владелец, fingerprint плана, порядок задач, идентичности и терминальные состояния квитанций. Текущая задача должна содержать исходный `generate_1` failure без публикации. Более ранние квитанции сохраняются без повышения их статуса или превращения в доказательства приёмки.

Запись производится только в новый каталог внутри существующего приватного каталога хоста: 0700 для каталогов, 0600 для файлов, exclusive creation, fsync, проверка исходных байтов и повторная удалённая проверка архива. Существующее состояние не перезаписывается. Неудачная или частичная запись сохраняется для разбора; автоматического удаления и повторения нет. Небезопасные пути, символические ссылки, чужой владелец плана и изменённые planning receipts отклоняются. Данные checkpoint не копируются в публичную метаинформацию.

В `calculatorRecoveryArtifactHost.ts` добавлен составной вход `restoreCalculatorRecoveryArtifactHost`. Он сначала проверяет checkpoint/receipt и соответствие сохранённому плану, затем восстанавливает метаданные и возвращает function-bearing recovery host. Ошибки имеют фиксированную диагностику без содержимого архива.

Это подготовка состояния, а не разрешение исполнения: результат содержит `executionAuthorized:false`. Контроллер бюджета, независимая проверка предшественников, remote claim и обычные Security/Reviewer/Tester/CI остаются обязательными в runtime.

## Чего этот этап не подтверждает

Регрессии используют синтетические архивы и mock HTTP. Новый реальный запуск модели или задачи не выполнялся. Подтверждённый ранее native ZIP audit остаётся проверкой транспорта синтетической метаинформации, а не реального приватного checkpoint задачи.

Для рабочего запуска ещё нужен производственный Actions entrypoint, собирающий genuine artifact + восстановленное состояние + native claim + обязательный project runtime + реальные проверки Node/browser. Хост обязан независимо закрепить полный исторический набор состояния, включая отсутствие более поздних начатых задач и crash locks: выборка файлов сама по себе не доказывает отсутствие других записей. Нельзя публиковать приватный исходник Onay в артефактах публичного Factory.

Новый допустимый источник задачи пока не выбран: историческая ошибка T05 не становится подходящей для generate recovery автоматически. Ledger проекта не инициализирован, operator `inspect`, ownerDecision `null`. T05 исчерпан: 11/11 запросов. Общая историческая консервативная оценка неизменна: 59 запросов, 553908 байтов, 230413 reserved tokens. Нужны подлинное согласование цели/нового бюджета и явная инициализация полной истории перед любым новым HTTP модели. Этот этап не сбрасывает счётчики.

Полная универсальная автономность и шаг 9 остаются открытыми. Юридический агент выключен. Codespaces, платные API и новые вспомогательные агенты не использовались.
