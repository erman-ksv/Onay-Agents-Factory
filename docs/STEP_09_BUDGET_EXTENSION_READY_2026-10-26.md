## Реализовано

- Отдельная проверка и операция расширения существующего ledger с сохранением всех reservations. Обычный append-only store по-прежнему запрещает подмену grant и удаление резервов.
- Разрешение привязано к полному SHA256 прежнего состояния. Требуются два подлинных native OWNER решения; новое решение должно быть отдельным неизменённым комментарием. Копии контроллера и поддельные permits отвергаются.
- Перед атомарным non-force CAS повторно проверяются оба owner решения. Конкуренция, устаревший revision, редактирование комментария и потерянный ACK приводят к безопасной остановке без повтора.
- Только новый подлинный grant позволяет отдельную фазу ревью. Обновление runtime само по себе не создаёт новый лимит.
- Workflow проверки работает только с read-only GitHub token, без модельных ключей. Workflow будущего ревью закреплён на исправленный проверенный runtime.
- Security, Reviewer, Tester, CI, авторизация и эталонные сценарии не ослаблены. Юридический агент выключен.
