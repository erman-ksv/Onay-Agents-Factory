# Factory — следующая задача после проверенного исправления

25 октября 2026. Продолжение [маршрута основного runtime](FACTORY_MAIN_RUNTIME_RECOVERY_2026-10-25.md).

## Проблема и результат

Отдельная фаза исправления уже могла получить кандидата с CI, но обычный selector видел исходный blocked receipt и останавливал план. Перезаписывать старую ошибку или без проверки считать её завершённой нельзя.

Добавлена краткоживущая host-capability `CalculatorVerifiedCorrection`. Обычный selector может использовать проверенный receipt исправления как подтверждение конкретной исходной задачи, сохраняя её старый blocked receipt и checkpoint. After-CI путь принимает эту связь и может выбрать ровно следующую задачу. Старое поведение без capability сохраняется: ошибка блокирует дальнейшую работу.

## Что проверяется

Host передаёт четыре приватных артефакта с внешними ожидаемыми SHA256: исходные checkpoint/receipt и checkpoint/receipt исправления. Самосогласованный JSON не подтверждает удалённое происхождение: обязательны настоящий callback удалённых доказательств, закреплённый CI-reader, чтение текущего head и host-проверка кандидата. Имитация этих функций используется только в тестах.

Связываются исходный план, задача Frontend, репозиторий, ветка, base/ bootstrap SHA и хеш отклонённого ответа. Из них заново выводится устойчивый executionId и точная identity отдельного correction receipt. Исходная запись должна подтверждать исходный отказ валидатора; исправленная — attempt 2 с ровно четырьмя запросами фазы, без неопределённого HTTP/ошибки, с предложением в допустимых путях и тремя успешными независимыми оценками без high/blocker. Обязательны все обычные этапы source/repair/roles/host tests/publication/CI, соответствующий опубликованный SHA и свежий зелёный CI с provenance и закреплённым task workflow. Метки receipt и JSON-модели сами по себе недостаточны.

Capability хранит приватные доказательства отдельно, а наружу отдаёт только task/commit/digest ссылки и `executionAuthorized: false`. Копия или JSON не действуют. Она не разрешает модель, не возвращает расходы и не заменяет общий grant.

Selector проверяет capability до и после асинхронных проверок зависимостей, использует прежние ancestry/blob/host проверки и повторно сравнивает все исходные receipts и locks перед выбором. Изменение следующей задачи во время финального удалённого вызова не может показать её ready. Красный CI, потеря удалённых доказательств и изменение исходной ошибки останавливают переход; отказ capability не снимается просто возвратом CI в зелёный.

After-CI проверяет исходную запись и её проверенное исправление, а прежний одноразовый event barrier запрещает повтор события. Проверенные связи передаются и в обычный claimNext, чтобы он не обходил защиту. Runtime принимает их только как зарегистрированные in-memory capabilities в доверенном after-CI вводе, привязывает метаданные к конфигурации и повторно проверяет их перед HTTP модели.

## Граница и оставшаяся работа

Capability привязана к текущему проверенному SHA исправленного кандидата: перенос на другой head без новой проверки запрещён. Подтверждён один ограниченный переход; произвольная последовательность последующих изменений и повторная интеграция исправления в новых commit ещё не подтверждены. Это не бесконечный автономный цикл проекта.

Для живого Actions-пути ещё нужен production host, который загружает аутентичные приватные артефакты и предоставляет настоящие remote source/claim/CI/test операции. Существующие исторические workflow не переключались. Разрешённый владельцем общий лимит и явная инициализация полной истории также остаются обязательными. Оператор остаётся `inspect`, `ownerDecision: null`, реальный ledger не активирован.

Реальных запросов модели — **0**, дополнительное разрешение — 0. Main и Calculator/Onay не изменены; пилот не повторялся, merge/deployment не выполнялись, Codespaces, платные API и новые агенты не использовались. Юридический агент отключён. Шаг 9 целиком не закрыт.
