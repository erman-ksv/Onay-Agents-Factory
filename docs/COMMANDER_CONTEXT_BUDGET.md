# Commander: исходники, доказательства и бюджет Groq

Область изменения: AI Commander в ветке `feat/specialist-qualification-20261017`.
Исходный коммит аудита: `971eef0b7b7bcfae5679e3c0aed43e42f7c1dff1`.

## Найденная повторная передача

В исходном `commander/aiExecution.ts` метод `explore()` сохранял полный текст и
возвращал тот же полный `Exploration`. В `commander/aiCommander.ts` обёртка
`executable()` сериализовала результат в историю модели. Следующий запрос
Commander снова содержал исходники. `specialistContext()` дополнительно соединял
полный контекст и полные предложенные файлы для каждого специалиста. Результат
Coder также содержал файлы, кроме отдельных запусков с private transform.

## Новая граница

- Полные неизменяемые копии исходных файлов, полного контекста и предложений
  остаются в памяти `AiExecutionSession`. Доверенные зависимости генерации,
  Security, Reviewer и публикации продолжают получать полные данные.
- Explorer возвращает только repository, commit SHA, пути, blob SHA, размеры,
  число строк и ссылки на файлы в конкретном коммите. Не более 64 файлов и
  12 000 символов сериализованных метаданных; превышение отклоняется.
- Commander получает от Coder метаданные предложений и SHA256, без содержимого
  файлов и без потенциально исходникосодержащих summary/message.
- Специалист получает пакет до 6 000 символов: до трёх фрагментов, каждый до
  1 500 символов. Строки нумеруются, пути и base/blob SHA сохраняются. SHA256
  предложения не выдаётся за SHA коммита.
- Пакет перечисляет непрочитанные файлы и диапазоны, отсутствие проверки
  исполнения/тестов и границу исследованного снимка. Неизвестное не считается
  доказанным отсутствием механизма или успешной проверкой.
- Рекомендации и их подробные findings хранятся у хоста. В Commander передаются
  ready, количества findings по severity и метаданные покрытия; советы не
  превращаются в доказательство исполнения.
- Подозрительные секреты в выбранном пакете отклоняются до отправки.
  Дополнительный host transform остаётся ограниченным тем же бюджетом; если
  он меняет пакет, исходное покрытие не заявляется подтверждённым.

Автоматический подбор использует задачу и роль. Для точной выборки хост может
задать `specialistSelections`: путь, source (`base`/`proposal`), начальную и
конечную строки. Только уже прочитанные исходники и имеющиеся предложения;
неизвестные пути, неверные диапазоны и превышение бюджета отклоняются без
содержимого файла в ошибке. Выборка `coder` отделена от `backend`, поэтому
ссылки backend на ещё не созданное предложение не используются при генерации.

Default Coder получает ограниченный пакет через модельный адаптер, а не полный
контекст. При недостаточных исходниках его инструкция требует отказаться от
реконструкции полного файла. Это не заменяет независимые проверки предложений.
Явно внедрённые хостом `dependencies.generate` остаются доверенной границей:
свой сетевой клиент в такой зависимости обязан соблюдать ту же политику.

## Groq: лимиты одного запуска

| Настройка | По умолчанию |
| --- | ---: |
| `GROQ_CONTEXT_BUDGET_TOKENS` | 6000 |
| `GROQ_RUN_BUDGET_TOKENS` | 16000 |
| `GROQ_TPM_BUDGET_TOKENS` | 6000 |
| `GROQ_RESERVED_OUTPUT_TOKENS` | 512 |
| `GROQ_MAX_REQUEST_BYTES` | 24000 |

Учитывается весь итоговый JSON запроса: instructions, схемы инструментов,
история и запрос. Оценка входа — `ceil(UTF8 bytes / 3) + 256`; это локальная
эвристика, а не точный токенизатор Qwen и не определение квоты аккаунта.
Отдельный лимит байтов проверяется точно. Максимум ответа ограничивается и
резервируется до отправки; несколько completions в одном запросе запрещены.

Один ledger разделяют Commander, его специалисты и default Coder. Резервы
синхронны и учитывают неуспешные HTTP-попытки с неизвестным расходом. Истечение
минутного окна не возвращает суммарный бюджет запуска.

При превышении лимита запрос не отправляется. HTTP 429 преобразуется в
фиксированную безопасную ошибку без чтения исходного тела ответа; сохраняется
только проверенный `Retry-After`. SDK retries Groq остаются равными нулю.
После отказа ledger и session останавливают дальнейшие запросы/инструменты,
включая уже поставленные в очередь действия. Автоматического ожидания,
переключения провайдера или повторения всей задачи нет. Результат содержит
`providerFailure` с причиной и безопасными числовыми метаданными.

Лимиты следует выбирать под реальный аккаунт/модель. Малый TPM может корректно
остановить многошаговый запуск; код не выдаёт такую остановку за завершение.

## Сохранённые проверки и пределы приёмки

Не меняются авторизация записи, allowlist репозитория, точные пути изменений,
проверки base/candidate SHA, инвалидирование оценок, Security, Reviewer,
Tester, CI gate и эталонные qualification-сценарии. Юридический агент в
конфигурации этого задания отключён: `AGENT_FACTORY_LEGAL_ENABLED=false`.
Сам существующий переключатель политики и его проверки не ослабляются.

Добавленные регрессии проверяют границу модели через SDK с подменёнными
транспортом/моделью, а также через чистые модули без внешних зависимостей.
Синтетическая квалификация специалистов не является доказательством реальной
работы с репозиторием. Реальные вызовы Groq и изменения Onay не выполняются.

Этот патч не переписывает отдельные deterministic Commander / pipeline /
retryLoop пути. Их полные доверенные контексты и сторонние injected-клиенты
нельзя считать автоматически переведёнными на выборочные фрагменты или общий
ledger AI Commander. Отдельный клиент через `configureModelProvider` получает
свой guard; общий ledger необходимо передавать явно.

Для полной приёмки обязательны `pnpm typecheck`, `pnpm test`,
`git diff --check`. Если SDK/TypeScript/tsx не установлены, отдельный запуск
через Node TypeScript transformation подтверждает только исполненный набор,
а не полный SDK-прогон или проверку типов.
