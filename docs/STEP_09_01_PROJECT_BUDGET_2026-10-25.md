# Шаг 9.1 — общий счётчик бюджета проекта

25.10.2026. Реализован первый подпункт шага 9: сохраняемый общий счётчик запросов, байтов контекста и резервных токенов, с подключением перед HTTP модели. **Полный шаг 9 ещё не завершён.** Рабочие сценарии Calculator автоматически на новый режим не переключались; новых вызовов провайдера и нового разрешённого бюджета нет.

## Зачем нужен

Лимит отдельной задачи не учитывает расходы других задач и новых экземпляров исполнителя. Команде нужен общий предел проекта, который хранится отдельно от процесса. Прежние расходы должны учитываться после перезапуска; оставшиеся токены не должны разрешать запрос, когда число запросов исчерпано.

## Что реализовано

- `projectModelBudget.ts`: явные параметры разрешения владельца, привязка к проекту, репозиторию, плану и историческим расходам. Автоматического разрешения или значения бюджета по умолчанию нет. Сама схема данных не доказывает согласие владельца: перед её использованием контроллер обязан проверить согласие и доказательства исторических расходов.
- Общий учёт запросов, полных байтов запроса и консервативного резерва токенов. Старые расходы входят в итог сразу; возвратов и сброса счётчика нет.
- Резервирование через сравнение версии и атомарную запись. Конфликт, неопределённое подтверждение или повторный идентификатор запроса останавливают попытку без автоматического повтора.
- `projectModelBudgetFileStore.ts`: запись в выделенном каталоге хоста, блокировка, атомарное переименование и fsync. Новые экземпляры счётчика читают уже сохранённые расходы. Чужая блокировка и ссылка вместо файла не удаляются и не обходятся.
- `taskModelBudget.ts`: явный host-only параметр `projectBudget`. Когда он задан, общая запись подтверждается **до HTTP**, одновременно с сохранением всех прежних локальных ограничений задачи. Неинициализированное хранилище не создаётся автоматически.
- Режим ограничен Groq; другой URL, поддельный счётчик, некорректная конфигурация и её последующая подмена не позволяют отправить запрос.
- В состоянии сохраняются идентификаторы, SHA256 запроса и числовые расходы. Полный исходник, сообщения модели и заголовок авторизации не сохраняются.

Для Groq используется прежняя консервативная оценка: `ceil(UTF-8 bytes / 3) + 256 + output limit`. Резерв не является денежным счётом провайдера. Существующие ограничения контекста, TPM и конкретной задачи остаются отдельными обязательными слоями.

## Что проверяется

- Новый экземпляр счётчика видит прежние расходы, не начинает бюджет с нуля.
- Синтетический пример с историей T05 **11/11 запросов, 43 761 резервных токенов** отказывает в новом запросе даже при остатке токенов. Настоящее состояние T05 этим тестом не мигрировалось и не изменялось.
- Одновременные клиенты не расходуют одну устаревшую версию дважды.
- HTTP 429 остаётся учтённым; восстановление с тем же идентификатором не повторяет запрос.
- Если запись состоялась, но её подтверждение потеряно, расход сохраняется, а HTTP не отправляется.
- Отмена во время записи останавливает последующий HTTP даже после завершения записи; резерв консервативно остаётся учтённым.
- Неверная схема, другой grant, чужая блокировка, повреждённое состояние и ссылка вместо файла дают отказ.
- В состоянии отсутствуют приватный контекст и ключи. Прежние сценарии TaskModelBudget сохранены.

## Границы готовности

Файловое хранилище предназначено только для процессов на **одном доверенном общем диске**. Оно не является удалённым общим хранилищем независимых GitHub Actions runners. Каталог должен принадлежать хосту и находиться вне рабочей копии, доступной агентам. Защита от произвольной подмены файлов самим владельцем хоста не заявляется.

Новый параметр включается только доверенным контроллером. Наличие этого модуля не означает, что все прежние способы вызова моделей уже используют общий бюджет. Legacy-сценарии не получили новых полномочий; T05 остаётся с исчерпанными 11 запросами.
