# Factory — сохранение ошибочного ответа разработчика

25 октября 2026. Продолжение [сохранения причин остановки](FACTORY_FAILURE_CHECKPOINT_2026-10-25.md).

**Основной runtime теперь сохраняет разобранный, но отклонённый ответ Developer/Frontend в приватную контрольную запись.** До этого ModelTeam уже предоставлял соответствующий callback, но runtime подключал только сохранение отклонённых проверок специалистов. Ошибочный ответ автора мог потеряться, оставляя для следующего исправления только код ошибки.

## Реализация

Подключён `afterProposalRejected` для обычного и проектного runtime. Сохранение разрешено только для текущей задачи, соответствующего этапа `generate_1` или `repair_2`, активного ожидающего запроса и состояния до публикации. Перепутанные задача, этап, попытка, тип ответа или состояние приводят к отказу.

Ответ остаётся недоверенными приватными данными `rejectedProposal`, а не подготовленным изменением. Он не проходит вместо Security, Reviewer, Tester или настоящих тестов. Ни сохранение, ни повторное чтение не дают разрешения применить код, повторить запрос или опубликовать результат. Для отдельного исправления остаются обязательными существующие проверки происхождения и бюджета.

Используется прежний защищённый кодировщик приватного JSON: ограничения объёма и глубины, отказ на секреты, циклы и вычисляемые свойства. Разрешения и проверки существующего сохранения оценок специалистов не ослаблены. В обычные метаданные попадают только тип, фиксированный код отклонения и SHA256 результата. Содержимое ответа находится только в приватном checkpoint; оно не добавляется в отчёт, лог или публичные метаданные.

Флаг `httpInFlight` очищается одновременно с успешным сохранением полного разобранного ответа. Если запись не удалась, прежняя неопределённость остаётся. Потеря подтверждения записи не вызывает второй попытки. При усечённом ответе, ошибке JSON или HTTP 429 callback не доказывает получение полного предложения и не очищает неопределённость.

Запись с отклонённым предложением остаётся заблокированной. Разрешено только дополнить её соответствующей окончательной причиной сбоя, сохранив исходный ответ и расходы. Изменить ответ, удалить его, засчитать как успешный либо продолжить тот же checkpoint нельзя. Общий callback ошибки исполнителя не стирает уже сохранённое доказательство.

Публичные метаданные не содержали ответа. Фиктивный вызов не является обращением к настоящему Groq.

## Границы результата

Старый формат без отклонённого предложения остаётся допустимым и не переписывается. Для новых записей с дополнительным полем нужен обновлённый валидатор; исторические потребители не ослабляются. Автоматический запуск нового исправления этим изменением не добавлен: подготовлено сохранение фактических данных для отдельно разрешённого исправления, без подмены кода человеком и без повторной генерации всего задания.

Реальных новых вызовов модели — **0**. Main и исходники Onay/Calculator не изменены; эталонные сценарии и ожидаемые ответы сохранены. Новый бюджет не разрешён и не активирован; запрос оператора остаётся `inspect`, `ownerDecision: null`. Пилот не повторялся; merge/deployment, Codespaces, платные API и новые агенты не использовались. Юридический агент отключён.

Доработка сохранения отклонённых ответов выполнена. Полная рабочая активация 9.3 и полезное выполнение 9.4 остаются открытыми: следующей задаче самой команды по-прежнему нужны цель, разрешённый общий лимит и явная активация счётчика.
