# Factory — окончательная остановка runtime между асинхронными операциями

25 октября 2026. Продолжение [оператора общего бюджета](STEP_09_03_ACTIVATION_OPERATOR_2026-10-25.md).

**Исправлена ошибка остановки команды:** при конкурентном вызове один клиент мог остановить runtime, а другой — продолжить отправку после ожидания разрешения или принять уже пришедший ответ. Ошибка синхронной проверки предложения также не закрывала остальные клиенты задач.

## Подтверждение проблемы

До исправления три новые детерминированные проверки завершились ошибкой `Missing expected rejection`. Использовались только локальные фиктивные ответы GitHub и модели. Реальные API моделей не вызывались.

| Сценарий | До исправления | После исправления |
| --- | --- | --- |
| Остановка, пока первый запрос ждёт проверки владельца | ожидавший запрос мог уйти | отказ до внешнего транспорта, 0 вызовов |
| Остановка, пока ответ уже отправленного запроса ещё ожидается | поздний ответ мог завершить операцию | поздний ответ отвергается; 1 учтённый вызов остаётся в расходах |
| Ошибка восстановления/проверки предложения | другой клиент задачи мог продолжить | все последующие операции закрыты, 0 вызовов |
| Запрещённое планирование через task-runtime | отказ не фиксировал общую остановку | отказ фиксирует общую остановку, последующая генерация запрещена |

Числа в таблице относятся к имитации внешнего транспорта в тестах. Расходы пользователя этими проверками не изменяются.

## Изменение

В `calculatorProjectRuntimeTeam.ts` добавлено единое состояние остановки для асинхронных и синхронных операций. Оно проверяется после ожидания TPM, после чтения разрешения владельца, непосредственно перед внешним транспортом и перед возвратом результата. Конкурентный вызов фиксирует остановку; завершение старого ожидания её не отменяет.

Уже отправленный запрос не возвращается из расходов. Поздний результат не становится успешным завершением задачи и не даёт разрешения на публикацию. Записанные проектные резервы также сохраняются, даже если до внешнего транспорта дело не дошло. Автоматического повторения задачи или вызова нет.

Диагностика теперь различает резервированные попытки и вызовы внешнего транспорта. Сохраняются причина общей остановки и безопасные коды ошибок клиента задачи, включая HTTP 429. Тела ответов, исходный код, предложения и ключи в эту диагностику не добавляются.
