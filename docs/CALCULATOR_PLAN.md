## Persistence and replay

`CalculatorPlanStore(directory, ownerRequest)` requires an owned 0700 directory.
It reuses the existing `TeamTaskStore` for locking, atomic private receipts,
identity validation and task replay barriers. The immutable plan document uses
0600, exclusive atomic creation, fsync, no symlink/hardlink following and bounded
source-free JSON. Its digest is anchored separately in the plan receipt. Missing
either document or marker, mismatched identity, interrupted initialization or
replaced directory stops; no automatic replan or replacement occurs.

`initialize(modelProposal)` stores the validated plan once; `inspect()` restores
it without models/network. Reinitializing identical content is idempotent;
different tasks under the same identity refuse. Task receipts bind both task ID
and the whole plan fingerprint. Deleting all local metadata is outside this
local replay barrier; preserve artifacts/history and do not reuse expired IDs.

## Choosing work

`select({currentBaseSha,verifyTask})` reads without claiming. No running, failed,
blocked or already-recorded task is automatically selected again. The first
unstarted task whose dependencies pass fresh host verification may be returned.
The first base must match the owner snapshot. A changed/unverified base, pending
CI or missing integration yields needs-review rather than stale execution.

Old status labels never suffice: each recorded candidate requires the fixed
calculator repository/plan branch and a fresh trusted-host callback checking
candidate SHA, integration into the current base, independent Security/Reviewer
and actual task checks. The callback must be supplied by the future host runner,
not a model tool or JSON response. This preparation step cannot independently
prove that callback's real tools ran. Step 6 provides actual base/integration
checks and step 7 wires execution and evidence.

The callback attests task-scoped checks only. A first arithmetic module can be
checked before the UI exists; its receipt does not pretend that browser or
whole-project CI passed. The full Calculator CI contract (Syntax, Unit tests,
Browser tests) remains mandatory for final application acceptance. Even
all-candidates-verified returns wholeAppCompleted=false/publicationAuthorized=false;
delivery documentation, independent final gates and owner acceptance are separate.

`claimNext(options)` must be used before a future runner invokes a model/tool.
It durably claims exactly one selected task, using existing TeamTaskStore locks.
The returned store is host-only and must be closed in finally. Interrupted work
requires reconciliation, not replay. Explicit new repair attempts, model calls,
GitHub writes, automatic continuation and project-wide quota are later steps;
they are not implemented or authorized by selecting a task.

No production calculator backlog was generated by a model in step 5. Handwritten
plans in regression fixtures are synthetic tests and must not be represented as
autonomous planning evidence.
