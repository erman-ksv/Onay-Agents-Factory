# Шаг 9.3 — подключение рабочего runtime без повторного пилота

25 октября 2026. Продолжение [предыдущего отчёта](STEP_09_03_OWNER_BUDGET_2026-10-25.md).

**Подключение общего бюджета к runtime реализовано. Перенос истории подготовлен без выдачи нового лимита. Повторный реальный прогон Calculator не выполнялся и не требуется для повторного подтверждения шага 8.**

## Что изменилось

Добавлен обязательный вход `runProjectBudgetedCalculatorRuntime`. Он передаёт в существующий исполнитель настоящий проверенный контроллер бюджета. Если режим `required` включён, отсутствие контроллера, JSON-подделка или попытка отключить бюджет приводят к отказу до обращения к модели. Конструктор не активирует хранилище и не поднимает лимит.

Внутри runtime задачи получают отдельные проверенные права на один общий проектный счётчик. Это относится и к Security, Reviewer и Tester при проверке зависимостей, и к Developer/Frontend следующей задачи. Лимиты запросов, времени, контекста и токенов в минуту дополнительно общие для всего runtime; создание другого клиента задачи их не обнуляет. Контрольные записи получают накопительную сумму всех клиентов. При HTTP 429, ошибке контрольной записи или исчерпании счётчика последующие вызовы других задач также прекращаются. Успевшие записаться резервы остаются учтёнными.

Приватная контрольная запись runtime дополнительно связана с ключом проекта, хешем разрешённого бюджета и ID выполнения. Старые квитанции задач, одноразовые барьеры событий, проверка точного SHA, реальные тесты, Security, Reviewer и Tester сохранены. Старые исторические workflow с закреплёнными версиями оставлены как доказательства; их повторный запуск не выполнялся. Будущий рабочий workflow должен использовать новый обязательный вход с разрешением на конкретную полезную задачу.

Пропущенные области или изменённые расходы приводят к отказу. Подготовка не создаёт разрешение и не инициализирует счётчик.

Read-only workflow проверяет уже существующий успешный CI проверенного runtime, неизменённые main и SHA Calculator, прежний успешный CI Calculator и отсутствие рабочего счётчика по целевому ключу. Он не получает ключей моделей и токена записи Calculator, имеет только права чтения, выполняет максимум пять GET-запросов GitHub и сохраняет только метаданные подготовки. При существующем счётчике отказ вместо перезаписи. Пакеты для этой проверки не устанавливаются.

## Точное состояние и следующий шаг

- **Шаг 8:** четыре исходных условия ограниченного пилота уже подтверждены, повторять пилот ради того же доказательства не нужно.
- **9.1 и 9.2:** готовы, проверки атомарного хранения сохранены.
- **9.3:** код обязательного рабочего входа и подготовка полной истории готовы. Реальное хранилище не активировано, решение о новом расходовании не выдано. Поэтому полная рабочая активация 9.3 пока не подтверждена.
- **9.4:** следующая полезная задача команды должна использовать новый вход. Проверку реального расходования общего счётчика совместим с этой задачей, после определения её цели и отдельного лимита. Специальный повторный прогон Calculator не запланирован.

Оставшаяся работа перед следующим полезным запуском: подтвердить цель и лимит, зафиксировать настоящее разрешение владельца, явно инициализировать общее хранилище полной историей, затем вызвать обязательный runtime через закреплённый workflow. Эти действия не подменяются подготовленным JSON или результатами тестов.
