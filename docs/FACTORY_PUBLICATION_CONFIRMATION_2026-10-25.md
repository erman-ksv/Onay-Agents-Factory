## Что изменилось

1. `github/calculatorSnapshot.ts` читает настоящий Git ref через `/git/ref/heads/<branch>`, проверяет точное имя ref, тип commit и 40-символьный SHA. Перенаправления запрещены. Нет fallback и автоматических повторов.
2. `github/calculatorPublisher.ts` сохраняет ограниченную диагностику этапа: операция, фаза, была ли попытка записи, подтверждён ли push, известный SHA кандидата и HTTP-статус. Сырые сообщения Git/HTTP, ответы сервера, исходник и токены не попадают в диагностику. Подлинность ошибки привязана к объекту в памяти; JSON-копия не даёт полномочий.
3. `orchestration/calculatorExecution.ts` переносит эту диагностику в остановленный отчёт. Существующие запреты повтора, квитанции, блокировки и требования CI остаются.
4. Добавлены восемь регрессионных тестов: устаревший commit lookup, неправильный ref/тип/SHA, отказы HTTP/redirect, фиксированная цель credentials, подтверждённый push с неверным последующим SHA, PR HTTP 403, потеря подтверждения/повторный no-op и безопасный отчёт без повторения моделей.
5. Обновлена только форма ответа прежней тестовой HTTP-заглушки под Git ref API. При проверке найдена устаревшая локальная копия execution-тестов: все три пропущенные проверки восстановлены до итогового CI. Все прежние именованные тесты сохранены; эталонные сценарии и ожидаемые ответы не менялись.

Не изменены Security, Reviewer, Tester, авторизация, force-with-lease, проверка точного родителя/путей, Draft-only, actual tests или CI. Юридический агент отключён.

## Что остаётся неподтверждённым

Старая публикация T04 остановилась после push с общим отказом. Старые логи не содержат фазы; восстановить точную причину по ним нельзя. Сегодня Git-ref endpoint и прежний commit endpoint возвращают одинаковый SHA. Это **не доказательство**, что старый сбой был вызван отставанием commit endpoint.

Реализованы прямое чтение ref и безопасная диагностируемость; новая реальная публикация после этих изменений **не выполнялась**. Поэтому не заявляется окончательное устранение исторического post-push дефекта. Следующая разрешённая задача должна подтвердить свежий push → ref → PR → CI; при отказе теперь останется точная фаза без автоматического повторения.

Итог шага 8 в ограниченном пилоте T03 → T04 → очередь T05 остаётся подтверждён прежним отчётом. Универсальная автономность и готовность всего Calculator не заявляются. T05 остаётся в ожидании бюджета: разрешено 0 новых запросов, из 8 запросов T04 использованы все 8. Автоматическая подписка на любые будущие CI и общий бюджет проекта остаются отдельной работой.
