26.10.2026. Продолжение существующей Factory, без изменения main, Onay и Calculator.

## Что исправлено

Раньше context-bound transport проверял исходящие запросы, но возвращал обычный объект ответа. Теперь production entry возвращает genuine capability: repository, plan, task, base commit, роль, SHA запроса/ответа и digest предложения. Сырой ответ хранится только в приватной памяти выполнения. Копия объекта и произвольный JSON не являются доказательством ответа модели. Явный host-only accessor нужен для доверенной обработки и диагностики.

Только bounded JSON настоящего ответа автора может создать предложение этого цикла. Действуют прежние проверки commit/source SHA, точных старых фрагментов, путей, секретов и статических политик. Нельзя подставить другое предложение, даже с тем же digest. Одноразовая обработка предотвращает повторное применение ответа.

Порядок запросов закреплён: **author → Security → Reviewer → Tester**. Следующий специалист получает то же genuine предложение и может быть запущен только после разбора положительного вердикта предыдущего. Пропуск, повтор, чужой proposal/task, устаревшие исходники, повреждённый ответ и неподтверждённый предыдущий результат останавливают цикл. Автоматического повтора и возврата расходов нет.

Вердикт имеет строгую схему: version, taskId, proposalDigest, decision, findings, unverifiedAreas. Неизвестные поля, выдуманное testsExecuted, неизвестные пути и ready с warning/error отклоняются. Отсутствие проверок остаётся явно указанным. При changes-requested/blocked замечания сохраняются для будущего исправления, но следующий запрос запрещён.

**Одобрение Tester — мнение модели. Оно не доказывает выполнение тестов.** Даже после четырёх положительных ответов runtimeTestsVerified, ciVerified, publicationAuthorized и wholeAppCompleted остаются false. Полный приватный исходник не может выйти через сериализацию ответа или assessment metadata. Отрицательные результаты и прежние резервы не удаляются.
