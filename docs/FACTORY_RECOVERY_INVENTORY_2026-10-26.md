# Factory: полный состав архива восстановления

26.10.2026. Изменение продолжает существующий Draft PR75 и ветку `feat/calculator-t02-charge-reconcile-20261022`.

## Проблема и результат

Прежний загрузчик проверял все ZIP пути на безопасность и проверял SHA выбранных файлов. Но восстановление плана работало с выбранными квитанциями: корректный архив мог содержать дополнительную квитанцию уже начатой следующей задачи или crash lock, которую хост не выбрал. Один факт наличия проверенных выбранных файлов не доказывал, что в архиве нет других записей состояния.

Добавлен `assertExactFiles` в genuine artifact capability. Проверка использует полный состав central directory из уже проверенных ZIP-байтов, а не только список `pin.files`. Все обычные записи должны точно совпадать с заданным набором и быть независимо закреплены/загружены. Неизвестные обычные файлы и посторонние каталоги отклоняются. Допустимы только каталоги-предки ожидаемых файлов. Дубликаты, небезопасные/пропущенные пути, lazy array properties и утрата remote provenance приводят к фиксированному отказу без содержимого файлов в диагностике.

`CalculatorRecoveryStateMapping` теперь явно требует `checkpointPath`. Восстановитель проверяет точный состав: сохранённый план + planning receipt + checkpoint + все квитанции до текущей задачи включительно. Это выполняется до записи состояния и дополнительных сетевых чтений. Checkpoint остаётся в доверенной памяти артефакта и не копируется в source-free receipt каталог. Составной host требует совпадения checkpoint path с источником.

## Область доказательства

Проверка доказывает отсутствие лишних файлов ВНУТРИ закреплённого ZIP. Она не доказывает, что процесс-сборщик скопировал все файлы исходного сервера. Полнота исходного сбора, отсутствие потерянных внешних locks/receipts и пригодность реального checkpoint остаются обязательными отдельными проверками производственного хоста. Новый метод не создаёт owner approval, бюджет, remote claim, модельный запрос или право публикации.

Существующие Security, Reviewer, Tester, CI, авторизация, ordinary runtime replay barriers и бюджетные счётчики не ослаблены. Старые терминальные квитанции не переписываются. Изменений приложений Calculator/Onay, main, merge или deployment нет. Юридический агент остаётся выключенным; новые агенты, Codespaces, платные API и запросы моделей не использовались.
